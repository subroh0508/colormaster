# i18n (compose-multiplatform-resources) 運用

> **5 行以内 summary**: ColorMaster の i18n は **compose-multiplatform-resources** を採用
> (ADR 0006)。旧 Kotlin/JS + `public/locale/` (i18next 系、ADR 0011 / 0012 で撤去対象) の
> 文言は C4 (EPIC-002) で CMP リソースへ移植する。本ファイルは現時点で確定している
> 文言 ID 命名規約 / ディレクトリ構造 / locale 追加手順を本文化し、C4 完了で確定する
> 事項は末尾 TODO 表に固定。

## 1. 採用 i18n 機構

| 項目 | 方式 | 関連 ADR |
|---|---|---|
| 文言リソース | `compose-multiplatform-resources` (`composeResources/values{-locale}/strings.xml`) | ADR 0006 |
| 旧 Web (撤去対象) | `i18next` + `public/locale/<locale>/translation.json` | ADR 0011 / 0012 |
| デフォルト言語 | **日本語 (ja)** (owner 第一言語、CMP の base locale) | ADR 0027 (テンプレ言語ポリシー) と整合 |
| 対応言語 | ja (default) / en (将来追加候補) | C4 で確定 |

## 2. 文言 ID 命名規約

形式: `<feature>_<category>_<key>`

- スネークケース、英小文字
- 最大 3 階層 (`feature_category_key`)
- 機能横断の共通文言は `common_*` プレフィックス
- 動的引数を含む文言は ID 末尾に `_with_args` を付けて区別

### 例

| 文言 | ID | 説明 |
|---|---|---|
| Home 画面タイトル | `home_title` | 機能名 + key |
| 検索フィルタのブランドラベル | `search_filter_brand_label` | feature + category + key |
| 共通: 戻るボタン | `common_back` | 共通プレフィックス |
| エラー: ネットワーク失敗 | `common_error_network` | 共通 + category + key |
| アイドル N 名選択中 | `myidols_selected_count_with_args` | 動的引数あり |

## 3. ディレクトリ構造 (CMP)

```
composeApp/src/commonMain/composeResources/
  values/strings.xml      (デフォルト: ja)
  values-en/strings.xml   (英語、将来追加)
  values-<locale>/strings.xml ...
```

詳細配置は C4 で `feature/` モジュール再構成と合わせて決定する。

## 4. locale 追加手順

1. `composeResources/values-<locale>/strings.xml` を新規作成
2. デフォルト (`values/strings.xml`) の **全キーを翻訳して同名キーで配置**
3. `./gradlew check` で missing translation を検出 (A6 で機械化、現状は目視)
4. PR description に追加した locale を明記、レビュー時に欠落キーがないか確認
5. Roborazzi baseline (A10 以降) は **新規 locale でも 4 パターン (mobile/desktop × Light/Dark)** を生成

## 5. 翻訳更新フロー

- **新規文言追加時は全 locale を同時に追加**。新規キーを 1 言語だけ追加して merge すると他 locale で fallback が走り UX が壊れる
- 翻訳のみ更新する PR は `chore(i18n): update <locale> translations` でコミット
- Conventional Commits 規約: `.claude/rules/commit-message.md`

## 6. 旧 `public/locale/` (i18next 系) の扱い

- `public/locale/<locale>/translation.json` は **撤去対象** (ADR 0011 / 0012)
- C4 (EPIC-002) で CMP リソースへ **文言単位で移植** し、移植完了モジュールから `public/locale/` を削除
- 移植中の暫定運用は C4 起票時に `EPIC-002/decisions.md` で決定
- 新規文言は CMP リソース側のみに追加 (`public/locale/` への追加は禁止)

## 7. 動的引数 (Plurals / String formatting)

- compose-multiplatform-resources の `stringResource(id, *args)` を使用
- 複数形 (plurals) は `<plurals>` 要素で定義 (C4 で実例追加予定)

## 8. 機械検証 (A6 で導入)

- `./gradlew check` で missing translation を CI 失敗扱いにする (Gradle カスタムタスク、A6)
- 文言 ID 規約 (`<feature>_<category>_<key>` の形式) を Konsist で検証 (A7 で `.claude/rules/i18n.md` 本格化と連動)

## Phase A〜C 持ち越し (C4 で本格化)

| 持ち越し項目 | 持ち越し先 | 理由 |
|---|---|---|
| 旧 `public/locale/` → CMP リソース 移植手順 (key マッピング表) | C4 (EPIC-002) | 撤去 Plan の中で実例を整備 |
| `values-en/strings.xml` の初期翻訳セット | C4 | 既存 ja キーが確定してから一括翻訳 |
| missing translation の CI 検出スクリプト | A6 | Gradle カスタムタスク (Markdown + i18n リソース) と統合 |
| 文言 ID 規約の Konsist rule | A7 | `.claude/rules/i18n.md` 本格化と連動 |
| Roborazzi baseline の locale 別生成 | A10 + C4 | locale 追加と UI 凍結のタイミング調整 |
| 複数形 (plurals) / 引数付き文言の実例 | C4 | 実装パターン確定後に追記 |
